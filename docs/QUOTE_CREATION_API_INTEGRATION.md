# Beige Quote Creation API Integration

This document describes the existing Beige.app quote APIs that can be used by an external automation service, such as quote generation from Quo call conversations.

## Environments

| Environment | API base URL | Client-facing app URL |
| --- | --- | --- |
| Development | `https://api.dev.beige.app/v1` | `https://dev.beige.app` |
| Production | `https://revure-api.beige.app/v1` | `https://beige.app` |

All endpoint paths below are relative to the API base URL.

## Access Model

Use a dedicated Beige internal user for this integration, for example `quotes-automation@beige.app`.

Why:

- Every quote already records `created_by_user_id`.
- Quotes created by automation can be filtered/reportable by that dedicated user.
- No individual sales rep credentials need to be shared with the integration.

Required user permissions:

- Quote create: `admin_quotes_all_quotes.create`, `sales_rep_quotes.create`, or `sales_admin_quotes.create`
- Quote read: `admin_quotes_all_quotes.view`, `sales_rep_quotes.view`, `sales_admin_quotes.view`, or `client_quotes.view`
- Quote edit/send: `admin_quotes_all_quotes.edit`, `sales_rep_quotes.edit`, or `sales_admin_quotes.edit`
- Invoice preview/send: quote/invoice read and quote edit permissions

Current note on `source`: the current `sales_quotes` table does not have a separate `source` column. The recommended current approach is to use the dedicated automation user. If a literal `source = automation` field is required, that is a small backend schema/API addition.

## Authentication

### Login

`POST /auth/login`

Request:

```json
{
  "email": "quotes-automation@beige.app",
  "password": "REDACTED"
}
```

Response:

```json
{
  "success": true,
  "message": "Login successful",
  "user": {
    "id": 123,
    "name": "Quotes Automation",
    "email": "quotes-automation@beige.app",
    "role": "sales_admin",
    "user_type_id": 1
  },
  "token": "JWT_ACCESS_TOKEN",
  "refreshToken": "JWT_REFRESH_TOKEN",
  "permissions": []
}
```

Use the `token` for all protected quote APIs:

```http
Authorization: Bearer JWT_ACCESS_TOKEN
Content-Type: application/json
```

## Quote Flow

Recommended automation flow:

1. Login and store the bearer token securely.
2. Create the quote as `draft` or `pending`.
3. Retrieve the quote to confirm totals/status.
4. Update the quote if the rep edits anything before sending.
5. Create or retrieve the public quote preview link.
6. Send the quote email when ready.
7. Optionally preview/send the invoice after the quote is accepted or ready for payment.

## Create Quote

`POST /sales/quotes`

Creates a sales quote using the same core fields as the admin Quotes module. The API calculates `subtotal`, `discount_amount`, `tax_amount`, and `total` from `line_items`, discount, and tax fields.

Request:

```json
{
  "status": "draft",
  "client_name": "Jane Client",
  "client_email": "jane@example.com",
  "client_phone": "+15551234567",
  "client_address": "Los Angeles, CA",
  "project_description": "Corporate interview shoot from Quo call summary.",
  "video_shoot_type": "Corporate Interview",
  "booking_type": "single_day",
  "time_zone": "America/Los_Angeles",
  "start_date": "2026-10-20",
  "start_time": "09:00:00",
  "end_time": "17:00:00",
  "quote_validity_days": 14,
  "discount_type": "fixed_amount",
  "discount_value": 250,
  "tax_rate": 0,
  "terms_conditions": "50% deposit due on approval. Remaining balance due before delivery.",
  "notes": "Generated by Quo automation.",
  "line_items": [
    {
      "source_type": "custom",
      "section_type": "service",
      "item_name": "Videography",
      "description": "Full-day videographer coverage.",
      "quantity": 1,
      "duration_hours": 8,
      "crew_size": 1,
      "rate_type": "per_hour",
      "rate_unit": "hour",
      "unit_rate": 250
    },
    {
      "source_type": "custom",
      "section_type": "addon",
      "item_name": "Teleprompter",
      "description": "On-camera script support.",
      "quantity": 1,
      "rate_type": "flat",
      "unit_rate": 250
    }
  ]
}
```

Important fields:

| Field | Type | Notes |
| --- | --- | --- |
| `status` | string | Usually `draft` before sending. Supported statuses include `draft`, `pending`, `sent`, `viewed`, `accepted`, `paid`, `rejected`, `expired`. |
| `client_name` | string | Required if no existing client/user is supplied. |
| `client_email` | string | Required before sending the quote. |
| `video_shoot_type` | string | Shoot type/category label shown on quote. |
| `line_items` | array | Quote services, add-ons, logistics, or custom items. |
| `discount_type` | string | `none`, `percentage`, or `fixed_amount`. |
| `discount_value` | number | Percent value or fixed dollar value depending on `discount_type`. |
| `quote_validity_days` | number | Alternative to `valid_until`; backend calculates expiry. |
| `valid_until` | date | Optional explicit `YYYY-MM-DD` expiry. |
| `terms_conditions` | string | Use this for payment plan terms. There is no separate payment-plan column today. |

Line item fields:

| Field | Type | Notes |
| --- | --- | --- |
| `source_type` | string | `custom` or `catalog`. Use `custom` for automation-generated items. |
| `section_type` | string | `service`, `addon`, `logistics`, or `custom`. |
| `item_name` | string | Display name. |
| `description` | string | Display description. |
| `quantity` | number | Defaults to 1. |
| `rate_type` | string | `flat`, `per_hour`, `per_day`, or `per_unit`. |
| `rate_unit` | string | Optional display unit such as `hour` or `day`. |
| `unit_rate` | number | Rate used for total calculation. |
| `duration_hours` | number | Used when `rate_type = per_hour`. |
| `crew_size` | number | Used for hourly/day calculations when relevant. |

Calculation:

- `flat`: `unit_rate * quantity`
- `per_hour`: `unit_rate * quantity * duration_hours * crew_size`
- `per_day`: `unit_rate * quantity * crew_size`
- `per_unit`: `unit_rate * quantity`

Success response:

```json
{
  "success": true,
  "data": {
    "sales_quote_id": 456,
    "quote_id": 456,
    "quote_number": "BQ-000456",
    "status": "draft",
    "client_name": "Jane Client",
    "client_email": "jane@example.com",
    "subtotal": "2250.00",
    "discount_type": "fixed_amount",
    "discount_value": "250.00",
    "discount_amount": "250.00",
    "tax_amount": "0.00",
    "total": "2000.00",
    "valid_until": "2026-11-03",
    "line_items": []
  }
}
```

## Get Quote

`GET /sales/quotes/{quoteId}`

Use this to retrieve status, totals, line items, invoice/payment context, activity history, and converted booking details.

Example:

```bash
curl -X GET "https://api.dev.beige.app/v1/sales/quotes/456" \
  -H "Authorization: Bearer JWT_ACCESS_TOKEN"
```

Success response:

```json
{
  "success": true,
  "data": {
    "sales_quote_id": 456,
    "quote_number": "BQ-000456",
    "status": "sent",
    "client_name": "Jane Client",
    "client_email": "jane@example.com",
    "total": "2000.00",
    "sent_at": "2026-09-14T12:30:00.000Z",
    "viewed_at": null,
    "accepted_at": null,
    "line_items": []
  }
}
```

## Update Quote

`PUT /sales/quotes/{quoteId}`

Use before the quote is sent, or when a permitted internal user needs to revise a quote. Send the same shape as Create Quote. If `line_items` is included, the provided line items become the active quote line items for the updated quote.

Request:

```json
{
  "client_name": "Jane Client",
  "client_email": "jane@example.com",
  "project_description": "Updated Quo summary.",
  "discount_type": "none",
  "discount_value": 0,
  "terms_conditions": "50% deposit due on approval. Balance due before delivery.",
  "line_items": [
    {
      "source_type": "custom",
      "section_type": "service",
      "item_name": "Videography",
      "description": "Full-day videographer coverage.",
      "quantity": 1,
      "duration_hours": 8,
      "crew_size": 1,
      "rate_type": "per_hour",
      "rate_unit": "hour",
      "unit_rate": 250
    }
  ]
}
```

Success response:

```json
{
  "success": true,
  "data": {
    "sales_quote_id": 456,
    "quote_number": "BQ-000456",
    "status": "draft",
    "subtotal": "2000.00",
    "total": "2000.00"
  }
}
```

Note: some edits close to the shoot start time may require `edit_reason` and `ops_review_confirmed: true`, depending on the existing quote schedule and payment state.

## Create Client-Facing Quote Link

`POST /sales/quotes/{quoteId}/preview-link`

Creates or refreshes the public quote preview key. Use this when the integration needs to return a shareable quote link to a rep or client before sending email.

Request body:

```json
{}
```

Success response:

```json
{
  "success": true,
  "data": {
    "quote_key": "PUBLIC_QUOTE_KEY",
    "expires_at": "2026-11-03T23:59:59.999Z"
  }
}
```

Build the client-facing URL:

```text
{CLIENT_APP_URL}/quotes/preview?quoteKey={quote_key}
```

Examples:

```text
https://dev.beige.app/quotes/preview?quoteKey=PUBLIC_QUOTE_KEY
https://beige.app/quotes/preview?quoteKey=PUBLIC_QUOTE_KEY
```

## Send Quote

`POST /sales/quotes/{quoteId}/send`

Sends the quote proposal email to the client. The backend also generates the quote PDF attachment and includes the quote preview/accept link.

Request:

```json
{
  "to_email": "jane@example.com"
}
```

`to_email` is optional if `client_email` exists on the quote.

Success response:

```json
{
  "success": true,
  "data": {
    "sales_quote_id": 456,
    "quote_number": "BQ-000456",
    "status": "sent",
    "sent_at": "2026-09-14T12:30:00.000Z"
  }
}
```

## Update Quote Status

`PATCH /sales/quotes/{quoteId}/status`

Use only when an internal workflow needs to set a quote status directly.

Request:

```json
{
  "status": "rejected"
}
```

Common statuses:

- `draft`
- `pending`
- `sent`
- `viewed`
- `accepted`
- `paid`
- `rejected`
- `expired`

## Public Quote Retrieval

These endpoints do not require authentication and are used by the client-facing quote preview page.

### Get public quote by quote ID

`GET /sales/quotes/public/{quoteId}`

### Get public quote by preview key

`GET /sales/quotes/public/by-key/{quoteKey}`

### Refresh latest public link by key

`GET /sales/quotes/public/by-key/{quoteKey}/latest-link`

### View Invoice PDF

Backend PDF endpoint:

`GET /sales/invoice-pdf/{bookingId}`

Frontend proxy URLs:

```text
https://dev.beige.app/beige-invoice/{bookingId}
https://beige.app/beige-invoice/{bookingId}
```

Optional query params:

| Param | Example | Notes |
| --- | --- | --- |
| `download` | `download=1` | Force PDF download on frontend proxy. |
| `receipt` | `receipt=1` | Return receipt version where available. |

| `manual` | `manual=1` | Manual invoice/receipt mode. |
| `manual_payment_id` | `manual_payment_id=123` | Select manual payment receipt. |

## cURL Example: End-to-End

```bash
# 1. Login
TOKEN=$(curl -s -X POST "https://api.dev.beige.app/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"quotes-automation@beige.app","password":"REDACTED"}' \
  | jq -r '.token')

# 2. Create quote
QUOTE_ID=$(curl -s -X POST "https://api.dev.beige.app/v1/sales/quotes" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "draft",
    "client_name": "Jane Client",
    "client_email": "jane@example.com",
    "project_description": "Corporate interview shoot.",
    "video_shoot_type": "Corporate Interview",
    "quote_validity_days": 14,
    "terms_conditions": "50% deposit due on approval.",
    "line_items": [
      {
        "source_type": "custom",
        "section_type": "service",
        "item_name": "Videography",
        "quantity": 1,
        "duration_hours": 8,
        "crew_size": 1,
        "rate_type": "per_hour",
        "rate_unit": "hour",
        "unit_rate": 250
      }
    ]
  }' | jq -r '.data.sales_quote_id')

# 3. Create public quote link
QUOTE_KEY=$(curl -s -X POST "https://api.dev.beige.app/v1/sales/quotes/$QUOTE_ID/preview-link" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' | jq -r '.data.quote_key')

echo "Quote URL: https://dev.beige.app/quotes/preview?quoteKey=$QUOTE_KEY"

# 4. Send quote email
curl -X POST "https://api.dev.beige.app/v1/sales/quotes/$QUOTE_ID/send" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
```

## Implementation Notes for the Client

- Store API credentials in a secure secrets manager.
- Do not expose the bearer token in browser-side code.
- Use idempotency on the client side if Quo can retry the same conversation. The current quote API does not expose an idempotency key.
- Use `notes` for internal automation context, for example the Quo conversation ID.
- Use `terms_conditions` for payment plan terms until a dedicated payment plan field is added.
- Use the dedicated automation user for attribution/reporting today.
